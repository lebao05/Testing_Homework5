# Skill: JMeter Test Plan Generator

## Purpose

Help the AI generate Apache JMeter `.jmx` test plans and CSV datasets for performance testing REST APIs. The AI produces the test plan **directly as text** — no Python scripts, no helper executables.

The skill supports:

- Load testing
- Stress testing
- Endurance / soak testing
- Spike testing
- Performance regression testing
- Multi-step user workflows (forgot-password → reset-password → login → search → cart, or any custom sequence)
- Dynamic values using JSON Extractors
- CSV-driven test data
- JTL result collection

> **Ask the user which type of test plan (Load, Stress, Spike, Endurance, …) if it is not clear from the request.**

Target JMeter version:

- JMeter: **5.6.3**
- Test format: JMX XML version 1.2

> ⚠️ **No Python scripts.** When the AI needs to generate a JMX, it writes the XML directly into the file with the Write tool.

> ⚠️ **This skill only generates the test plan.** Running JMeter, starting the SUT, and analyzing the JTL are handled by `log-analysis-skill.md` and are the user's responsibility.

## 1. Required Input

Before generating a test plan, identify:

### System Under Test (SUT)

- Look at `eshop-sut/` for source code (routes, `database.js` seed, response shapes).
- Base URL (default: `http://localhost:3000`)
- Host (`localhost`)
- Port (`3000`)
- API endpoints
- HTTP methods
- Request body schema
- Expected response codes
- Required authentication (Bearer token? cookie? header?)

### Test Configuration

- **Test type** — Load, Stress, Endurance, Spike
- **Number of VUs** (e.g. 50 / 200 / 300)
- **Ramp-up time** (seconds)
- **Duration** (seconds, via `ThreadGroup.duration`)
- **Think time** (per-step, in ms)
- **CSV dataset path** (absolute path on disk)
- **JTL output path** (absolute path so JMeter cwd does not matter) — see Output Folder Convention below

### Output Folder Convention

All artifacts generated by this skill MUST be written under `Agent-Skill/output/`. Use these exact paths:

- JMX: `D:\Testing\HW5\Agent-Skill\output\<workflow>_<TestType>_<YYYYMMDD>.jmx` (e.g. `register_search_cart_Load_20260816.jmx`)
- CSV: `D:\Testing\HW5\Agent-Skill\output\<workflow>_users.csv` (e.g. `register_search_cart_users.csv`)
- JTL target (listener `filename`): `D:\Testing\HW5\Agent-Skill\output\results\<workflow>_<TestType>_<YYYYMMDD>.jtl`

`<workflow>` is a short snake_case slug of the workflow steps (`register_search_cart`, `forgot_login_search_cart`, etc.). `<TestType>` matches the §5 preset exactly (`Load`, `Stress`, `Spike`, `Endurance`). `<YYYYMMDD>` is today's date in the user's locale.

Inside the JMX, both `CSVDataSet.filename` and `ResultCollector.filename` must be these **absolute** paths — never `results/load.jtl`-style relative paths (JMeter's cwd is `<bin>/`).

> ⚠️ `Agent-Skill/output/results/` may not exist on first generation. Create it by writing an empty `Agent-Skill/output/results/.keep` file with the Write tool before referencing the JTL path. JMeter silently fails to write JTLs if the parent directory is missing.

Do **NOT** write generated artifacts into `test-plans/load/`, `test-plans/stress/`, or `test-plans/strike/` — those directories hold the canonical, validated reference test plans and must remain stable across regenerations.

### Workflow

The user provides the workflow in this form:

1. `POST /api/forgot-password`
2. `POST /api/reset-password`
3. `POST /api/login`
4. `GET /api/products?search=<keyword>`
5. `POST /api/cart`

This is the canonical **5-step auth → read → write** workflow used across the existing test plans. Any new workflow slots into the same shape (each sampler with a JSON Extractor for the next step, an `Authorization` HeaderManager on protected calls, a `ResponseAssertion` for status codes, and a `ConstantTimer` for think time).

## 2. Configuration Consistency Rule

Verify the configuration is internally consistent before generating. Examples:

```text
Test type: Stress
VUs: 500
Ramp-up: 15 seconds
Duration: 30 seconds
→ Coherent: 500 VUs fully online after 15s, sustained for 30s.
```

```text
Test type: Spike
Spike-A: 200 VUs, ramp 5s, duration 30s
Spike-B: 300 VUs, ramp 5s, duration 30s
Cooldown between bursts: 45s
→ Spike-B delay = 5 + 30 + 45 = 80 seconds (must be a literal integer on <longProp name="ThreadGroup.delay">)
```

If the numbers don't work, **flag it before generating**.

## 3. CSV Dataset Convention

The CSV row count must match the seeded-user count in `database.js`. Across the existing test plans:

```csv
email,search_keyword,new_password
perf-user-001@load.com,ao thun,Newpass123!
perf-user-002@load.com,giay the thao,Newpass123!
```

| Field | Convention |
|---|---|
| `email` | `perf-user-NNN@load.com`, zero-padded to 3 digits, N up to the seed count |
| `search_keyword` | 60/30/10 mix — 60% miss, 30% hit, 10% wildcard (round-robin assignment) |
| `new_password` | Constant `Newpass123!` |

The CSV must be generated **before** running JMeter. The AI writes the CSV file directly with the Write tool:

- 500 rows
- Header line: `email,search_keyword,new_password`
- Round-robin over the keyword pool
- For keywords containing `,`, `"`, or newline, wrap in `"..."` and double `"` to escape
- Replace `email` / `password` variable names per the workflow (e.g. `register` flow uses `password` column; `forgot-password` flow uses `new_password`)

```csv
reg-user-001@load.com,ao thun,Newpass123!
reg-user-002@load.com,giay the thao,Newpass123!
```

## 4. The Reference Test Plan Structure

This is the canonical JMX structure distilled from the three existing test plans. **Use this as the template** for any new endpoint addition or new test plan:

```
TestPlan
  └─ TestPlan (TestPlan.comments: workflow description + listener note)
       └─ User Defined Variables (UDV)
       │    ├─ baseURL = http://localhost:3000
       │    ├─ thinkStep1..N = 0..5000 ms
       │    └─ (test-specific vars: stress_users, stress_ramp, stress_dur, etc.)
       └─ ThreadGroup (one or more)
            ├─ HeaderManager     ← TG-level: Content-Type + Accept (REQUIRED)
            ├─ CSVDataSet        ← absolute path, recycle=true, shareMode=currentThread
            ├─ UniformRandomTimer (ConstantTimer.delay=0, RandomTimer.range=1000)
            ├─ (Optional) GenericController wrapping the workflow
            ├─ sampler 01: first step
            │    ├─ JSONPostProcessor: extract {value}
            │    └─ ConstantTimer: thinkStep1
            ├─ sampler 02: second step
            │    ├─ (Optional) ResponseAssertion
            │    └─ ConstantTimer: thinkStep2
            ├─ sampler 03: ...
            │    ├─ ResponseAssertion: Assert 200
            │    ├─ JSONPostProcessor: extract token
            │    └─ ConstantTimer: thinkStep3
            ├─ IfController: only run protected steps if token ≠ NOT_FOUND
            │    ├─ sampler 04: protected GET
            │    │    ├─ JSONPostProcessor: extract product_id
            │    │    └─ ConstantTimer: thinkStep4
            │    └─ sampler 05: protected POST
            │         ├─ HeaderManager: Authorization Bearer ${token}  ← sampler-level override
            │         └─ ResponseAssertion: Assert 2xx
            └─ ResultCollector(s)
                 ├─ Aggregate Report (guiclass="StatVisualizer")  → absolute JTL path
                 └─ (Optional) View Results Tree (live only, empty filename)
```

### Required XML fragments (copy-paste ready)

**TG-level HeaderManager** — REQUIRED for every POST/sample to work. Without it, body-parser rejects the body and `req.body` is undefined.

```xml
<HeaderManager guiclass="HeaderPanel" testclass="HeaderManager" testname="HTTP Header Manager">
  <collectionProp name="HeaderManager.headers">
    <elementProp name="" elementType="Header">
      <stringProp name="Header.name">Content-Type</stringProp>
      <stringProp name="Header.value">application/json</stringProp>
    </elementProp>
    <elementProp name="" elementType="Header">
      <stringProp name="Header.name">Accept</stringProp>
      <stringProp name="Header.value">application/json</stringProp>
    </elementProp>
  </collectionProp>
</HeaderManager>
```

**Authorization HeaderManager** (only on the protected sampler, overrides TG-level):

```xml
<HeaderManager guiclass="HeaderPanel" testclass="HeaderManager" testname="Authorization">
  <collectionProp name="HeaderManager.headers">
    <elementProp name="" elementType="Header">
      <stringProp name="Header.name">Authorization</stringProp>
      <stringProp name="Header.value">Bearer ${token}</stringProp>
    </elementProp>
  </collectionProp>
</HeaderManager>
```

**IfController** — skip the protected flow if token extraction failed:

```xml
<IfController guiclass="IfControllerPanel" testclass="IfController" testname="If token missing, skip protected steps">
  <stringProp name="IfController.condition">${__javaScript("${token}" != "NOT_FOUND")}</stringProp>
  <boolProp name="IfController.evaluateAll">false</boolProp>
  <boolProp name="IfController.useExpression">true</boolProp>
</IfController>
```

**JSON Extractor** (with `defaultValues=NOT_FOUND` for the cascade-detect):

```xml
<JSONPostProcessor guiclass="JSONPostProcessorGui" testclass="JSONPostProcessor" testname="JSON Extractor token">
  <stringProp name="JSONPostProcessor.referenceNames">token</stringProp>
  <stringProp name="JSONPostProcessor.jsonPathExprs">$..token</stringProp>
  <stringProp name="JSONPostProcessor.match_numbers">1</stringProp>
  <stringProp name="JSONPostProcessor.defaultValues">NOT_FOUND</stringProp>
  <boolProp name="JSONPostProcessor.error_on_variable_failure">false</boolProp>
</JSONPostProcessor>
```

**CSV Data Set** (always use these settings):

```xml
<CSVDataSet guiclass="TestBeanGUI" testclass="CSVDataSet" testname="CSV Data">
  <stringProp name="delimiter">,</stringProp>
  <stringProp name="fileEncoding">UTF-8</stringProp>
  <stringProp name="filename"><ABSOLUTE PATH TO CSV></stringProp>
  <boolProp name="ignoreFirstLine">true</boolProp>
  <boolProp name="quotedData">true</boolProp>
  <boolProp name="recycle">true</boolProp>
  <stringProp name="shareMode">currentThread</stringProp>
  <boolProp name="stopThread">false</boolProp>
  <stringProp name="variableNames">email,search_keyword,password</stringProp>
</CSVDataSet>
```

**POST sampler (raw body)**:

```xml
<HTTPSamplerProxy guiclass="HttpTestSampleGui" testclass="HTTPSamplerProxy" testname="03 POST /api/login">
  <intProp name="HTTPSampler.connect_timeout">5000</intProp>
  <intProp name="HTTPSampler.response_timeout">10000</intProp>
  <stringProp name="HTTPSampler.domain">localhost</stringProp>
  <stringProp name="HTTPSampler.port">3000</stringProp>
  <stringProp name="HTTPSampler.protocol">http</stringProp>
  <stringProp name="HTTPSampler.contentEncoding">UTF-8</stringProp>
  <stringProp name="HTTPSampler.path">/api/login</stringProp>
  <stringProp name="HTTPSampler.method">POST</stringProp>
  <boolProp name="HTTPSampler.use_keepalive">true</boolProp>
  <boolProp name="HTTPSampler.postBodyRaw">true</boolProp>
  <elementProp name="HTTPsampler.Arguments" elementType="Arguments">
    <collectionProp name="Arguments.arguments">
      <elementProp name="" elementType="HTTPArgument">
        <boolProp name="HTTPArgument.always_encode">false</boolProp>
        <stringProp name="Argument.value">{"email":"${email}","password":"${password}"}</stringProp>
        <stringProp name="Argument.metadata">=</stringProp>
      </elementProp>
    </collectionProp>
  </elementProp>
</HTTPSamplerProxy>
```

**GET sampler with query param**:

```xml
<HTTPSamplerProxy guiclass="HttpTestSampleGui" testclass="HTTPSamplerProxy" testname="04 GET /api/products?search=">
  <intProp name="HTTPSampler.connect_timeout">5000</intProp>
  <intProp name="HTTPSampler.response_timeout">10000</intProp>
  <stringProp name="HTTPSampler.domain">localhost</stringProp>
  <intProp name="HTTPSampler.port">3000</intProp>
  <stringProp name="HTTPSampler.protocol">http</stringProp>
  <stringProp name="HTTPSampler.contentEncoding">UTF-8</stringProp>
  <stringProp name="HTTPSampler.path">/api/products</stringProp>
  <stringProp name="HTTPSampler.method">GET</stringProp>
  <boolProp name="HTTPSampler.use_keepalive">true</boolProp>
  <boolProp name="HTTPSampler.postBodyRaw">false</boolProp>
  <elementProp name="HTTPsampler.Arguments" elementType="Arguments" guiclass="HTTPArgumentsPanel" testclass="Arguments" testname="User Defined Variables">
    <collectionProp name="Arguments.arguments">
      <elementProp name="search" elementType="HTTPArgument">
        <boolProp name="HTTPArgument.always_encode">true</boolProp>
        <stringProp name="Argument.value">${search_keyword}</stringProp>
        <stringProp name="HTTPArgument.use_equals">true</stringProp>
        <stringProp name="Argument.name">search</stringProp>
        <stringProp name="HTTPArgument.content_type"></stringProp>
      </elementProp>
    </collectionProp>
  </elementProp>
</HTTPSamplerProxy>
```

**Aggregate Report listener** (the actual report writer):

```xml
<ResultCollector guiclass="StatVisualizer" testclass="ResultCollector" testname="Aggregate Report">
  <boolProp name="ResultCollector.error_logging">false</boolProp>
  <objProp>
    <name>saveConfig</name>
    <value class="SampleSaveConfiguration">
      <time>true</time><latency>true</latency><timestamp>true</timestamp>
      <success>true</success><label>true</label><code>true</code>
      <message>true</message><threadName>true</threadName><dataType>true</dataType>
      <encoding>false</encoding><assertions>true</assertions><subresults>true</subresults>
      <responseData>false</responseData><samplerData>false</samplerData><xml>false</xml>
      <fieldNames>true</fieldNames><responseHeaders>false</responseHeaders>
      <requestHeaders>false</requestHeaders><responseDataOnError>true</responseDataOnError>
      <saveAssertionResultsFailureMessage>true</saveAssertionResultsFailureMessage>
      <assertionsResultsToSave>0</assertionsResultsToSave>
      <bytes>true</bytes><sentBytes>true</sentBytes><url>true</url>
      <threadCounts>true</threadCounts><idleTime>true</idleTime><connectTime>true</connectTime>
    </value>
  </objProp>
  <stringProp name="filename"><ABSOLUTE PATH TO .jtl></stringProp>

```

> ⚠️ **JMeter's cwd is `<bin>/`** when launched via `jmeter.bat`. A `filename="results/load.jtl"` will write to `<bin>/results/load.jtl`, not where you wanted. **Always use absolute paths** like `D:\Testing\HW5\test-plans\load\results\load.jtl`.

> ⚠️ **`AggregateReportGui` does NOT exist in JMeter 5.6.3.** Use `StatVisualizer`. Using `AggregateReportGui` produces `ClassNotFoundException: AggregateReportGui` and `Could not get GUI` in `jmeter.log`. The Window still opens but the listener panel is blank.

## 5. Test-Type Presets

### Load test (50 VUs, 30s sustained)

```xml
<ThreadGroup guiclass="ThreadGroupGui" testclass="ThreadGroup" testname="Load-50VU-30s">
  <intProp name="ThreadGroup.num_threads">50</intProp>
  <intProp name="ThreadGroup.ramp_time">5</intProp>
  <longProp name="ThreadGroup.duration">30</longProp>
  <longProp name="ThreadGroup.delay">0</longProp>
  <boolProp name="ThreadGroup.same_user_on_next_iteration">true</boolProp>
  <boolProp name="ThreadGroup.scheduler">true</boolProp>
  <stringProp name="ThreadGroup.on_sample_error">continue</stringProp>
  <elementProp name="ThreadGroup.main_controller" elementType="LoopController" guiclass="LoopControlPanel" testclass="LoopController" testname="Loop Controller">
    <intProp name="LoopController.loops">-1</intProp>
    <boolProp name="LoopController.continue_forever">false</boolProp>
  </elementProp>
</ThreadGroup>
```

Think times: 2000 / 5000 / 3000 / 5000 ms (realistic pause).

### Stress test (200 VUs, 10 min sustained)

Same as Load, but with `num_threads=200`, `duration=600`, and `thinkStep1..4=0` (no thinking — pure throughput). Use parameterised UDV so the values can be overridden:

```xml
<elementProp name="stress_users" elementType="Argument">
  <stringProp name="Argument.name">stress_users</stringProp>
  <stringProp name="Argument.value">200</stringProp>
</elementProp>
<elementProp name="stress_ramp" elementType="Argument">
  <stringProp name="Argument.value">30</stringProp>
</elementProp>
<elementProp name="stress_dur" elementType="Argument">
  <stringProp name="Argument.value">600</stringProp>
</elementProp>
```

Then reference them in the `ThreadGroup`:

```xml
<stringProp name="ThreadGroup.num_threads">${stress_users}</stringProp>
<stringProp name="ThreadGroup.ramp_time">${stress_ramp}</stringProp>
<stringProp name="ThreadGroup.duration">${stress_dur}</stringProp>
```

> ⚠️ **UDV overrides `-J` properties.** If you pass `jmeter -Jthreads=200` and `threads` is also in UDV, UDV wins. Either remove the UDV or use `${__P(threads,50)}` inside the UDV.

### Spike test (200 then 300 VU bursts with cooldown)

Two **top-level ThreadGroups** with explicit `ThreadGroup.delay`:

```xml
<!-- Spike-A: 200 VUs, ramp 5s, duration 30s, delay 0 -->
<ThreadGroup ... testname="Spike-A">
  <intProp name="ThreadGroup.num_threads">200</intProp>
  <intProp name="ThreadGroup.ramp_time">5</intProp>
  <longProp name="ThreadGroup.duration">30</longProp>
  <longProp name="ThreadGroup.delay">0</longProp>
  ...
</ThreadGroup>

<!-- Spike-B: 300 VUs, ramp 5s, duration 30s -->
<!-- delay = 5 + 30 + 45 = 80 (literal integer, NOT ${__javaScript(...)} — see below) -->
<ThreadGroup ... testname="Spike-B">
  <intProp name="ThreadGroup.num_threads">300</intProp>
  <intProp name="ThreadGroup.ramp_time">5</intProp>
  <longProp name="ThreadGroup.duration">30</longProp>
  <longProp name="ThreadGroup.delay">80</longProp>
  ...
</ThreadGroup>
```

> ⚠️ **JMeter top-level ThreadGroups run in parallel, NOT sequentially.** A "Cooldown" ThreadGroup with `delay=0` is **not** a cooldown — it starts at t=0. Use `ThreadGroup.delay` on the second burst to simulate serial bursts.
>
> ⚠️ **`ThreadGroup.delay` is a plain integer** — `Long.parseLong()` is called before function substitution. Using `${__javaScript(5+30+45)}` produces `NumberFormatException`. Hard-code the result and document the arithmetic in `TestPlan.comments`.

## 6. JMX Validation Checklist

After generating the JMX, run these checks yourself with the Grep tool before handing it to the user:

- [ ] Top tag is `<jmeterTestPlan version="1.2" properties="5.0" jmeter="5.6.3">`
- [ ] TG-level `HeaderManager` is present with `Content-Type` and `Accept` (otherwise POSTs fail to parse)
- [ ] `CSVDataSet filename` is an **absolute** path
- [ ] `CSVDataSet shareMode` is `currentThread`
- [ ] `CSVDataSet variableNames` matches the CSV header
- [ ] At least one `JSONPostProcessor` is present (for token / id extraction)
- [ ] `IfController` exists if the workflow has a skip-block (e.g. `if token != NOT_FOUND`)
- [ ] At least one `ResponseAssertion` matches the expected status code
- [ ] Authorization HeaderManager is on the protected sampler (sampler-level)
- [ ] Listener `guiclass="StatVisualizer"` (NOT `AggregateReportGui`)
- [ ] Listener `filename` is an **absolute** path
- [ ] `ThreadGroup.duration` is set (otherwise the loop runs forever)
- [ ] `ThreadGroup.num_threads` matches the test type
- [ ] `loop` count is `-1` (infinite, capped by duration)
- [ ] Each sampler has a `ConstantTimer` referencing `thinkStepN` for the post-step pause
- [ ] Sampler label starts with `NN ` (two-digit zero-padded) so the analysis output is sorted

## 7. Generation Procedure

1. **Read `Prompt.md`** (or the user's request) to identify the workflow and test type.
2. **Read the closest-matching existing JMX** in `test-plans/` to confirm the exact shape of variables, listeners, and assertion patterns.
3. **If the test type is unclear** (Load vs Stress vs Spike vs Endurance), ask the user one short clarifying question. **Do not** ask "should I write a JMX" or "should I run JMeter".
4. **Write the CSV** directly with the Write tool to `D:\Testing\HW5\Agent-Skill\output\<workflow>_users.csv` (500 rows, 60/30/10 keyword mix). Use the Output Folder Convention from §1 for the exact path.
5. **Write the JMX** directly with the Write tool to `D:\Testing\HW5\Agent-Skill\output\<workflow>_<TestType>_<YYYYMMDD>.jmx`. **No Python scripts.** Copy structure from §4, apply the preset from §5. Both `CSVDataSet.filename` and `ResultCollector.filename` inside the JMX must use absolute paths under `D:\Testing\HW5\Agent-Skill\output\…` (never relative).
6. **Validate the JMX** against the §6 checklist (Grep the file with the AI's own tool — no Python).
7. **Hand off the artifacts** to the user. They will start the SUT, invoke JMeter, and analyze the JTL using `log-analysis-skill.md`.

## 9. What the AI Does NOT Do in This Skill

- ❌ Start the SUT or stop it
- ❌ Invoke JMeter through the agent's shell
- ❌ Read or analyze the JTL
- ❌ Write the performance report
- ❌ Write Python scripts to generate JMX

The AI only **generates** the CSV dataset and JMX file as text, then validates them against §6. Running and reporting are the user's job (covered by `log-analysis-skill.md`).
